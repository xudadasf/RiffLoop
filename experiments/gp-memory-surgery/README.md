# GP 压缩包内存替换实验

`archive_edit.py` 只在内存中替换 ZIP 内的 `Content/score.gpif`，不读取路径、不写文件、不接入正式程序。实验先用独立的 `archive_guard` 检查原存档，然后保留其他成员的完整本地记录、元数据、描述符和内容，只更新主谱相关尺寸、CRC 与后续目录偏移，再调用 `archive_guard` 检查候选存档。

遇到未知额外字段、加密、ZIP64、不支持的压缩参数、含糊的数据描述符、常见的签名或签名清单条目、资源差异等情况会拒绝。该识别仅覆盖常见文件名，无法排除其他签名方式。对反序描述符必须显式启用。该检查不解析谱面，不证明目标音符、技巧、音高、签名、外部软件显示与播放正确，因此绝不能据此保存或覆盖用户谱。

运行：`python -B -m unittest discover -s experiments/gp-memory-surgery -p 'test_*.py'`。测试覆盖五种合成 ZIP 布局与拒绝情况。本地还对一份经过筛选的开发谱执行了仅重压主谱的无修改对照：资源检查通过，解压后的主谱相同，源文件哈希未变；这不是音符编辑成功率，也不是独立验证集。

`observation.py` 的实验辅助函数可把同一份内存归档交给本地读取器，并将其主谱内容的摘要与观察值关联；反序描述符需要显式启用。摘要只能关联调用方提供的数据，不能证明读取器结论正确。观察结果可能包含私人谱面数据，不应记录或上传。

读取快照分别记录主小节的速度变化、伴奏同步点、每拍音色自动化以及轨道初始音色库、MIDI 端口和通道，避免把数值相同但所在位置不同的类型混淆；同步点的缺失列表与空列表分别保留。对读取器加载的伴奏，仅在本地记录是否存在、字节长度和 SHA-256，不记录音频内容；观察结果及其摘要不能上传或写入日志。合成测试覆盖同步时间、音色库、速度标注以及伴奏资源引用的变化。这里仅是内置读取器中已列出的字段对照，不证明所有自动化、其他软件或实际播放兼容。
