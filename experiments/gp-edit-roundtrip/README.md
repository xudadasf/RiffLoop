# 离线 GP 修改往返实验

此实验使用现有的 alphaTab，直接在内存中读取 GP、修改一处品位与断音，以及在总时长不变的前提下调整相邻两个等时值音符（例如把两个四分音符改成一个八分音符和一个附点四分音符），重新导出后读取。实验不写入 GP 文件，不更改原谱，也不接入练习播放器。

在仓库根目录运行：`node experiments/gp-edit-roundtrip/test.cjs`。单独评估兼容谱例：`node experiments/gp-edit-roundtrip/probe.cjs 原谱路径`。程序只输出所检查字段发生变化的位置，不输出谱面内容。未找到适合编辑的普通音符时会报告跳过，不能视为通过。

只比较代码中明确列出的部分字段。它不能发现未列出的技巧、布局、附件或伴奏等丢失，也不检验声音和 iPad 真机表现，不能据此声称 GP 编辑无损。资源检查另见 `scripts/gp-roundtrip-audit.py`；现有 GP 文件暂不应交给草稿编辑器覆盖保存。

## 开发样例的资源检查

对本机 12 份开发素材运行现有资源审计：9 份可按 GP ZIP 结构完成审计，均发现未修改谱面直接往返后存在归档项缺失或变化；2 份不符合此脚本要求的 ZIP 结构，1 份读取或导出失败。失败和未覆盖的样例不能算通过。这些素材是开发样例，不是独立的准确率测试集。

其中两份也用于上述编辑实验的谱子，所检查的音符字段往返一致，但每份都有 9 个归档项缺失（含目录项）、2 个变化。缺失的项目包括谱面视图、样式及偏好设置文件，二进制样式和布局配置内容也发生改变；是否影响具体显示需在兼容的 GP 软件中另行验证。另有一份样例在选定字段中出现 6 处推弦控制点偏移量浮点末位差异，约为 `1e-14`，不应直接判为可听见的错误。

复现命令：`python scripts/gp-roundtrip-audit.py 原谱路径`。省略 `--output-dir` 时仅使用系统临时目录，不保留导出文件；工具会清理临时文件，且不会修改输入。脚本只支持它能识别的 GP ZIP 格式，并仅检查已列出的语义字段及除谱面主文件外的归档资源；检查通过也不能证明无损。实验导出的文件不得覆盖用户原谱。

系统临时目录可能位于 C 盘；本次在运行脚本前将进程的 `TEMP` 和 `TMP` 指向 D 盘测试目录，以减少 C 盘占用。

## 直接修改 GPIF 的风险

只读抽查素材目录的前 60 份开发样本，52 份可解析为 ZIP 内的 GPIF；另外 6 份不是 ZIP，2 份的 XML 解析失败，原因未确定。这不是独立验证集。52 份可解析样本均有带音符的 Beat 被多处引用，47 份有带品位的 Note 被多处引用，51 份有共用 Rhythm；52 份均含额外 ZIP 资源及 Fret、Midi 属性。直接修改共享节点可能改变谱中其他位置，单改品位也可能与保存的音高不一致。

GPIF 的引用链包括 `MasterBar → Bar → Voice → Beat → Note`，时值另由 Beat 引用 Rhythm；实际文件还可能包含移调、连音、滑音、弯音等关联。后续若试验直接修改，应先用合成样本验证复制共享节点、重建引用、同步音高与保留资源，并检查目标外内容；任何无法验证的情形均需拒绝覆盖原谱。当前没有实现或验证这一保存方式。

## 品位修改后的升号残留

使用仓库测试谱的内存实验，将一个原先带强制升号的音符改为品位 4 后，导出的 MIDI 为 59，但谱内音名仍写作 B 升号；相同品位和 MIDI 的新建音符则写作 B 自然音。重新读取后强制升号状态仍在。测试不包含声音，也未使用 Guitar Pro 验证实际显示和播放，因此不能推断听感或界面一定错误，但它表明只比较品位和 MIDI 不足以保证编辑结果一致。

`python -B -m unittest discover -s experiments/gp-edit-roundtrip -p 'test_accidental_regression.py'` 包含一项明确的预期失败，用于记录此限制；测试通过不意味着此问题已解决。

简单地将升降号设回默认值也不能保证保留原谱写法：合成对照中，同一音高的强制降号写作 B♭，恢复默认后写作 A♯；移调设置也会影响输出的记谱音名。调号下的音名语义还需独立编辑器验证，因此目前不将重置默认值作为通用修复。
