# GP 附加资源保留检查实验

`archive_guard.py` 只比较两份内存中的 ZIP 数据，不读取或写入用户文件，也不接入应用。它检查成员顺序、名称、常见 ZIP 元数据、归档注释和除 `Content/score.gpif` 外的解压内容及原始本地记录（包括压缩数据）；遇到重复成员、路径异常、加密或超出限制等情况会拒绝。该检查会读取测试谱，但不会修改或提取它。

运行：`python -B -m unittest discover -s experiments/gp-archive-safety -p 'test_*.py'`。

默认只接受常见的数据描述符顺序；本机开发素材中还发现部分描述符将压缩前后长度反序存放。实验的 `allow_reversed_descriptor=True` 可明确启用该顺序，并检查修改前后不能悄悄切换。对前 60 份开发素材只读自比：启用后 52 份 ZIP 通过这一层检查，2 份因单项超过当前 64 MB 上限被拒，6 份并非 ZIP。自比未修改谱面，也不是编辑成功率；暂未验证反序文件在不同 GP 软件中的兼容性。

这只是一道资源对照，不验证主谱面改动是否正确，也不证明整个 ZIP 的所有字节、数字签名、Guitar Pro 兼容性或播放保持不变。通过它并不代表可覆盖原谱；后续仍需验证音符引用、时值和音高，并采用独立副本保存。
