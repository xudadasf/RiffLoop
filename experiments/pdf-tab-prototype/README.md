# PDF 六线谱 → GP 独立实验

## 电脑试用入口

双击本目录的 `start-desktop.cmd`（本机桌面另有 **RiffLoop PDF 六线谱试用** 快捷方式）。新窗口标题含 **图片 / PDF 草稿 · 支持默认占位 · 2026-10-27**；升级前打开的旧窗口需手动关闭后重新启动。点击“添加 PDF / 截图”可多选文件，再点击“开始处理待处理文件”。完成后点击“打开 GP 草稿”编辑，或“查看结果 / 问题”核对数字框、时值和占位清单。

默认结果目录为 `D:\RiffLoop-model-tests\pdf-tab-desktop`，没有 D 盘时使用用户 Documents 下的 `RiffLoop-PDF-results`；窗口内可更改。每份文件、每次处理都创建独立目录，不覆盖旧结果。文件只在本机处理。可在当前文件完成后停止队列，剩余文件可继续；单份任务最长等待 15 分钟。

支持两种路径：电子六线谱 PDF 保留现有矢量识别；**PNG/JPEG/WebP/BMP/TIFF 截图、照片，以及含扫描谱页的 PDF** 使用本地数字 OCR 与弦线定位。图片会做 EXIF 转正、轻微倾斜校正、灰度处理和六线谱行定位。扫描/混合 PDF 整份使用像素识别，不读取其文字或矢量音符答案。每次最多 40 页，多张图片各自生成对照报告，不自动拼成一曲。

图片现在可生成**带明确占位的可编辑 GP 草稿**。窗口默认 **100 BPM、4/4**，允许修改；结果报告和 `recognized.json` 的 `manual_settings` 记录实际人工设置。数字 OCR 负责弦号/品位，明确连接的符干和横梁用于识别简单时值；不能确认的时值按用户要求使用默认占位，在谱中只标 `?`，详细内容写入独立修改清单。未知时值默认四分音符，剩余小节空间不足时统一缩短；剩余时长填休止占位。若已识别时值与拍号冲突，整小节节奏降为明确标记的默认值。不会把占位报告为识别成功。旧专用模型保持停用，不自动回退；也不把缺失品位编造为空弦。

用户练习图实际导出的 GP 已读回核对：4 小节、64 个单音的弦号/品位/顺序与人工记录一致；60 个时值由横梁识别，4 个使用十六分音符占位；每小节均为 4 拍。整页复杂谱仍有大量未解决区域，只能作为需大量人工编辑的草稿，不能宣称通用准确率。和弦同时分组、多声部、附点与连音、技巧、反复尚未可靠恢复。小节位置来自谱线几何；某页没有六线谱时仍停止并标明页码，不能凭空恢复谱行结构。

依赖：Python（tkinter、PyMuPDF、OpenCV、NumPy、Pillow）和 PATH 中的 Node.js。数字 OCR 独立 Python 位于 `D:\RiffLoop-model-tests\raster-tab-20261027\digit-ocr-env\Scripts\python.exe`，模型目录为 `D:\RiffLoop-model-tests\raster-tab-20261027\digit-ocr-probe\models`，可用 `RIFFLOOP_DIGIT_PYTHON` / `RIFFLOOP_DIGIT_MODELS` 配置。入口检查本地模型存在，记录输出和模型哈希；环境缺失则报告失败，不回退旧模型。此入口仅为本机试验，未打包第三方权重。

命令行可执行 `python desktop_gui.py`，或传入多个文件路径预先加入列表。工作器 `--image-settings` 接受 JSON `tempo`、`meter` 和可选 `tuning`；缺省字段使用 100 BPM、4/4、标准六弦定弦。参数不传给 OCR 模型；拍号用于校验已识别时值及安排明确占位，不影响矢量 PDF。移动端未修改。当前能力见 [图片时值与占位导出记录](IMAGE-DRAFT-20261027.md)；[入口切换记录](IMAGE-ENTRY-FIX-20261027.md) 和 [旧模型接入记录](IMAGE-TRIAL-20261027.md) 保留历史阶段状态。

## 电子 PDF 原有规则如何识别

只输入 PDF，不读取原 GP。用 PyMuPDF 提取 PDF 本身的文字绘制记录和线条：六条等距横线确定弦位，线上的数字确定品位，符干、横梁、附点和连音数字确定时值。然后按小节检查拍数。这里没有调用大模型，也没有上传素材。

选择文字绘制记录而非普通文本段，是因为排版提取可能把相邻的 `14、15、14` 合并成 `141514`。这仍依赖 PDF 的字体和绘制方式，不是通用 OCR。

空小节仅在拍号明确、谱面区域没有未知标记时恢复为整小节休止。页脚只有同时匹配 PDF 实际页序/总页数、页面底部位置、谱线下方距离和右侧对齐，且候选唯一时，才从空谱面检查中排除；其他文字、分数、图形以及缺少拍号的情况继续阻止推断。

六线谱下方的节奏附点按符干位置归属：搜索区域截止到下一根符合节奏位置的符干或小节边界，避免密集音符中把后一音的附点重复计入前一音；仍保留原有距离范围及真实附点，不按总拍数删减符号。

六线谱内的可见延音还会检查括号数字的实际边界，避免 `(11)`、`(14)` 等较宽标记超出固定中心距离而被漏掉；前后必须是相邻节拍，同弦同品，并有实际连接弧线。休止或其他音符隔开时不连接。

当延续和弦的六线谱数字被隐藏时，可通过五线谱恢复一部分：要求前后完整音头组位置相同，每个音都有独立连接弧线，目标具有节奏符干，且中间没有其他节拍。仅补全整组证据充分的延音，不按缺少的拍数猜音符。

另接受位于音头上方或下方的独立短延音弧：端点须对齐音头中心，竖向距离限定在五线谱间距的 0.4–0.8 倍，并继续要求相邻同位置音头、唯一弧线、隐藏目标和真实符干。和弦须逐音都有独立弧线，一条共用弧不能代替多条延音证据。弧线须完整位于六线谱上方，不用固定的 5 点留白排除贴近谱线的真实弧线；不按拍数差补音。

五线谱上方的三连音数字须具有唯一双侧水平括号及两个向下端钩，括号完整位于同一小节，范围内恰有三个已识别时值的普通节拍，且与已分配连音不冲突。没有括号的数字、指法、跨小节括号及数量不符的组合不采用。

六线谱里部分可见的和弦也能补回一部分隐藏延续音：目标已有至少两个实际印出的音符，待补弦没有已有数字，弧线两端位于来源弦附近，并指向该和弦的符干。中间有其他节拍或目标是休止时不推断；只有一个可见音符时需要下述额外证据，不能仅凭附近短弧补成和弦。

连续延音的隐藏数字可能留下较宽的空位。超出原弧线匹配距离时，只有同弦两段弧线在唯一符干两侧对称、后一段明确连到同弦同品的括号数字，且中间没有其他节拍，才补回隐藏延续音；不会单纯扩大所有弧线的距离容差。

如果中间连续多拍都隐藏品位数字，可沿弧线逐段检查后续符干，直到同弦同品的可见括号数字。扩展路径只跨过完全隐藏的节拍，每一步都必须有独立弧线、唯一符干、对称间距和连续小节；整条路径成立后才补音。缺少末端证据、弧线有歧义，或中间出现休止、可见音符、部分可见和弦时，不能用这条扩展路径越过。

对末端直接接休止或新音的情况，另从同页至少两处同字体、同字号的可见括号与入弧测量留白：先扣除实际数字宽度的一半，核对括号及边距一致，再加上来源音实际数字宽度的一半；不按位数假设字形等宽。同一和弦的多根弦只算一个排版位置。只有隐藏位置与测量值匹配、前后弧线同弦、目标符干唯一，并通过连续小节、休止和可见音符检查时才恢复延音。恢复音保留独立测得的宽度，后续弧线可继续使用。字体、字号、留白不一致或样本不足时不采用，不读取参考 GP 推算间距。

当前页缺少充分测量时，可从同份 PDF 的其他页取得样本：要求相同实际字体资源、字号及六线谱间距，至少两个独立位置，并且跨页及本页的可用留白测量一致。仅字体名称相同不够；其余弧线、隐藏位置、唯一符干和连续节拍检查仍保留。

延音和弦只印出一个括号音符时，只有该音符已确认从来源和弦延续、遗漏弦还有独立弧线与实测留白证据，才能补回该弦；普通单音、不同品位或尚未确认延音的括号音符不能用作这个依据。

另一根弦重新起音时，可另通过完整的隐藏延音链恢复：至少两处独立括号样本确认留白，目标隐藏位置有唯一且对称的入弧/出弧，下一位置也有相同实测留白及唯一符干，且中间没有其他节拍。这条路径要求完整隐藏链，不凭单个短弧线补音。

隐藏延音在一个新起音旁结束时，另支持来源已经确认为延续的实际括号单音：弧线起终点须同时匹配独立测得的括号留白、保持同弦，目标符干唯一且为相邻拍的另一弦普通新音。重复弧、缺少测量、H/P/sl. 标记、来源未确认、目标休止/装饰音/闷音/括号音/泛音等情形仍拒绝；旧音只延长，新音保持独立起音。

全休止与二分休止的轮廓很相似，进一步依靠谱线位置区分：从第二线下垂或放在第三线上，同时排除连接符干的短横梁。位置不明确时仍不采纳。括号延续音或已恢复的隐藏延续音，在具有明确位置和长度的独立短符干时可识别为二分音符。

纯六线谱中，无符干的括号延续音仅在严格条件下识别为全音符：本小节只有该节拍、每个音都有独立弧线连接前一连续且校验通过的小节、同弦同品，且周围没有其他未知标记。按全音符本身的时值读取，再检查拍号，不按缺失拍数填充。空白区域检查在相邻谱行之间截断，避免把下一行的高位标记算入本行；品位数字两侧的短谱线片段也按已确认弦线位置排除。

全音符延续的空白区域检查现在区分已确认图形：从自带字体模板辨认的轮廓 TAB 谱号、从当前括号音通向同弦同品后续括号音或谱行边界的唯一延音弧，以及谱下两条唯一配对、闭合且对称的渐强/渐弱线。其他未知标记仍阻止推断；渐强/渐弱的实际力度变化尚未导出。

字形模板先以双倍分辨率绘制，再归一化比较，减少空心音头边缘失真；相似度与歧义门槛保持不变。五线谱的叉形音头仅在对应六线谱明确标为闷音时参与时值识别，并要求实际符干证据，再读取横梁或符尾。

`symbols.py` 使用仓库现有字体的字形模板识别轮廓符号，低相似度或无法消除歧义时不采纳，不从 GP 答案训练模板。`recognize.py` 生成音符数据及原谱标记图，`gp-export.cjs` 通过仓库已有 alphaTab 1.8.4 写出 GP7 格式，并重新读取检查导出是否改变数据。`convert.py` 把这两步串起来。只有评估工具才允许读取 GP 答案。

单音连奏滑音要求 `sl.`、与品位方向一致的斜线、上下方的连接弧线共同指向同弦相邻单音。支持谱行顶部的文字及同一行中的跨小节连接；缺少任一证据不推断。GP 回读检查滑音类型和目标；片段截断已识别连接时阻止导出。未解决标记记录在 `slide_marks`，实验稿仍可能缺少其他滑音及技巧。

平移和弦滑音要求前后弦集合相同、每根弦品位移动量相同且非零，每根弦都有方向正确的独立斜线，和弦外侧还有共用弧线。支持上侧、下侧或双侧弧线，每侧只能有唯一对应；密集音符之间的短斜线还须完整位于两端数字之间。图形证据完整时不要求 `sl.` 文字；缺线、部分音不动、改变和弦形状、弧线位于和弦内部或跨休止时不推断整组滑音。同一谱行内只连接相邻节拍。

跨行及跨页滑音另要求行尾斜线延伸到右边界，两端外侧弧线对应，且前行末拍和后行首拍弦集合相同、品位变化量一致。单音仍需行尾 `sl.` 文字；两端小节编号须连续且拍数检查通过。缺少边界证据、跨休止或部分弦滑动时不推断。

单音顿音通过明确的 Bravura 上方/下方顿音字形与唯一节拍对应；另支持本行 TAB 上方位置、大小和归属均明确的孤立轮廓圆点，包括音乐字体与轮廓混合的页面。轮廓候选须避开上一行节奏区、普通及轮廓文字，并且唯一对应一个普通单音；不将字体附点改为顿音。GP 导出和回读保留逐音顿音属性，缩短声音而不改变原时值及起音位置。和弦级圆点无法唯一还原原 GP 的逐弦属性时记入 `staccato_marks`，不按整组推断；其他轮廓圆点位置仍不支持。

密集排版的单音滑音斜线按弦线间距检查最小宽度，并要求线条完整位于两端数字之间；仍需方向、弧线及 `sl.` 文字同时成立。同弦多个音共用连奏弧线时，每段都须有唯一的 H/P/sl. 标记及对应方向证据，不能跨过休止或不明过渡。支持明确的装饰音滑向普通音，装饰音拍前/拍上位置仍受下述边界限制。

掌根闷音要求明确的 `P.M.` 文字；连续范围还要求相邻虚线、末端竖线及唯一对应的起止节拍。端点按品位数字实际右边缘匹配，范围可跨同一谱行中的小节；无标记时不跨行延续。仅恢复确定的单音属性，混合范围中的和弦归属留在 `palm_mute_marks`，不一律给整组加闷音。

连续滑音也可共用一个位于整段弧线中心的 sl.，要求整段同弦、无歧义且每个过渡有证据。 当弧线同时包含 H/P 时，先逐段确认这些标记的唯一归属及品位方向；其余至少两段须连续、共用的 sl. 位于该滑音组中心，并逐段满足原有滑音证据。缺标记、方向冲突、分组不连续或弧线有歧义时不推断，也不会把 H/P 段改成滑音。数字间距小于弦距的 0.6 倍时可接受没有斜线，但仍须显式文字和唯一弧线，且不可存在冲突斜线；宽间隔缺线不推断。

支持明确的单音波音/回音符号，包括文字与轮廓混合的 PDF。以 Bravura 模板辨认四种符号，要求唯一对应普通单音，导出后回读类型并验证 MIDI 起音；真实素材目前仅验证了《默》的五个上波音。

支持文字或轮廓形式的三斜杠重复拨弦，时值限于普通四分音符及普通/3:2 三十二分音符，且为无附点单音。符号须穿过同列真实六线谱符干；六线谱没有符干时，另要求上方五线谱有唯一实心音头、连接该音头的真实符干及穿过符干的同类标记。密集标记按音头与符干的连接关系筛选，不仅按距离选择。导出与回读保留原时值、连音比例和重复拨弦属性。当前可评估素材中的 42 处标记全部对齐，另有 7 处来自不可评估素材，仍为未验证。和弦、附点、其他时值/连音比例及斜杠数量尚未支持。详见 [《七重人格》整曲与播放库限制](VALIDATION-20261015-upper-rhythm.md)。

## 电子 PDF 严格流程的边界

- 面向可提取文字及矢量线条的六弦电子 PDF，当前重点支持 Arial/Helvetica 品位数字和部分 SMuFL 音乐符号。扫描 PDF、照片、四弦贝斯、鼓谱不支持。
- 默认处理单分谱、单声部；小节号缺失、顺序异常或重复会阻止整曲导出。未解决的拍数问题也阻止导出。
- 必须从 PDF 找到标准定弦文字和初始 BPM。未识别拍号时，4/4 仅用于诊断并标为 `assumed-4/4`，对应小节禁止导出。BPM 暂按四分音符计拍，因此仍不能保证通用速度标记的解释正确。
- 支持可提取的文字或轮廓四分音符速度符号及数字明确对应小节起点时的瞬时变速，片段导出继承起始小节的有效速度。发现数字速度标记但无法确认单位或小节起点时，阻止导出；初始 BPM 保留上述旧规则。其他计拍单位、小节内部变速、渐快渐慢及更多轮廓字形尚未支持，纯文字变化提示也未完整检测。
- 支持部分图形休止符、已确认拍号下的无未知标记空白小节、圆圈二分/全音符、附点、3/5/6/7 连音，以及有明确弧线和符干证据的隐藏延音。可连接一部分跨行/跨页的可见括号延音：要求小节连续、前小节拍数检查通过；六线谱逐音要求可见括号、同弦同品的唯一来源及两侧无歧义的对应弧线，允许和弦的其他弦重新起音。只在五线谱出现弧线时，仍要求完整和弦相同、每个音都有边界弧线。跨行隐藏品位、部分和弦延音、装饰音类型、推弦、滑音、泛音、击勾弦、反复结构、变调及中途变速均未完整实现。装饰音暂按八分时值、拍前装饰音导出；括号本身不作为延音证据。延音源不在所选片段内时阻止导出。
- 绿色框**仅表示拍数合计通过**，不能证明音符、顺序或演奏技巧正确。没有完整的正确性置信度。
- 默认转换整份 PDF；任何小节有未解决问题即不输出整曲。可以显式选择已核对的连续片段。导出标题和文件名均标为实验稿。

## 初版验证存档（2026-10-06）

输入为用户本地素材目录。先用少量 PDF 调试规则，再冻结识别规则进行批量评估；之后仅增加假设说明和导出检查，未根据保留样本继续调参。

82 组自动候选配对中：50 组完成逐小节对比，14 组存在多分谱或重复小节号，4 组未找到六线谱，14 组因两个原始 GP 文件无法由当前 alphaTab 导入而无法评估。失败项保留在报告中。两份 GP 是可读取的 ZIP 容器，但导入器报告 `No compatible importer found for file`；尚未定位内部格式差异，不能据此判断原文件损坏。

| 已完成对比的候选样本 | 音符匹配率 | 音符覆盖率 | 音符及节奏覆盖率 |
| --- | ---: | ---: | ---: |
| 全部 50 组 | 95.56% | 91.48% | 77.72% |
| 其中未参与调试的 47 组 | 95.41% | 91.53% | 78.45% |

这些是按音符总数加权的诊断指标，不是整曲成功率。自动配对可能不正确，GP 多轨时在评估阶段选择匹配最多的六弦轨道，因此也不是严格盲测成绩。同一曲子的不同分谱并不统计独立。

- 音符匹配率 = 弦位/品位匹配数 ÷ PDF 识别音符数。
- 音符覆盖率 = 匹配数 ÷ GP 全部音符数，包含漏识别的音符。
- 音符及节奏覆盖率额外要求时值、附点、连音比例、是否装饰音一致。
- 匹配限制在同号小节内，以最长公共子序列对齐。不评估休止符完整性、技巧、延音、拍号、速度变化或反复结构。JSON 中 `exact_bars` 也只表示音符/上述节奏属性及拍数检查通过，不表示小节完整正确。
- 每份预测先独立写入 JSON 并保存 SHA-256，再读取参考 GP；识别器和导出器都没有 GP 答案参数。

已实际生成并重新读入、再对照原 GP 的两个片段：

| PDF | 原谱小节 | 音符数 | 结果 |
| --- | --- | ---: | --- |
| 七重人格 | 10–13 | 96 | 所检查项目全部一致；调试样本 |
| 变相怪杰 吉他2 | 8–39 | 255 | 所检查项目全部一致；未参与调试 |

片段检查包括第 1 声部的音符/休止节拍序列、弦位、品位、闷音、时值、附点、连音、装饰音标志、拍号、定弦和初始速度。没有验证技巧、延音、反复、中途变速和实际听感。片段选在批量结果中可导出的小节，因此不能用它们推断整曲成功率。《变相怪杰》这份 PDF 的全部 775 个音符及所测节奏属性匹配，但仍有 16 个空小节/休止符小节未解决，整曲导出会被阻止。

脱敏后的逐素材结果保存在 `validation-summary.json`。完整原谱、GP 答案和生成文件仅保存在本地 `output/pdf-tab-prototype/`，不提交到 Git。

## 使用

依赖 Python 3.10+、Node.js；本次环境为 Python 3.14、PyMuPDF 1.27.2.3、Node 24.14.0。以下命令在仓库根目录运行。

安装 PDF 解析依赖：

```powershell
python -m pip install -r experiments/pdf-tab-prototype/requirements.txt
```

弹出文件选择窗口，完成后打开结果文件夹（不自动安装依赖）：

```powershell
pwsh -STA -File experiments/pdf-tab-prototype/run.ps1
```

也可指定 PDF。每次输出使用独立文件夹：

```powershell
pwsh -STA -File experiments/pdf-tab-prototype/run.ps1 -PdfPath 'C:\谱子\练习.pdf' -Bars '10-13'
```

命令行转换，输出目录应专用于本工具。同目录重跑会替换结果，并清除旧的 `experimental.gp`，避免失败后误用旧稿：

```powershell
python experiments/pdf-tab-prototype/convert.py 'C:\谱子\练习.pdf' --out output/pdf-tab-prototype/manual
```

输出包括 `review.html`（逐小节说明）、`overlay.pdf`（蓝框音符、红框待核对小节）、`recognized.json`。只有拍数检查及导出回读检查通过才生成 `experimental.gp`。

```powershell
python -m unittest discover -s experiments/pdf-tab-prototype -v
```

批量独立识别后对照答案（需要用户本地素材，运行约数分钟）：

```powershell
python experiments/pdf-tab-prototype/evaluate.py 'C:\Users\sadada\Desktop\素材' --out output/pdf-tab-prototype/benchmark
```

查看生成的 `report.html`。仅更新报告显示可加 `--report-only`。候选配对规则为同目录同名、同目录唯一 GP、最后才是文件名相似度；人工复核配对和轨道是解释结果的前提。

从已有评估生成错误分类及配对分组，无需重新识别：

```powershell
python experiments/pdf-tab-prototype/diagnostics.py output/pdf-tab-prototype/benchmark-20261009 --pairing-baseline output/pdf-tab-prototype/benchmark-20261008-wide-ties
```

输出 `diagnostics.html` 和 `diagnostics.json`，按每个参考小节的首个不同层级分类，包含未识别到的小节。`--pairing-baseline` 将分组固定到同一批历史候选，避免识别变化导致样本跨组；省略时使用当前自动分组。配对有一致性支持不代表版本完全相同，两个分组及不支持/读取失败的样本都保留。

报告另列“节奏优先检查”，数据中为 `rhythm_counts` 和 `rhythm_differences`：按第一声部的逐拍时值、装饰音标志、起音/延续/休止状态及拍号比较。总拍数相同但中间拍位错误仍不通过。此项忽略品位、弦位和和弦音符数量，只用于定位节奏问题，不验证速度、反复、中途变速、装饰音具体落点或实际听感。

验证一个导出片段与原 GP 的指定轨道：

```powershell
python experiments/pdf-tab-prototype/verify_export.py output/pdf-tab-prototype/heldout-demo/experimental.gp 'C:\Users\sadada\Desktop\素材\花花\变相怪杰\变相怪杰.gp' --track '吉他2' --bars 8-39 --out output/pdf-tab-prototype/heldout-demo/verification.json
```


输出 `palm-mute-audit.json`；来源范围未确认或和弦逐弦归属不明时不算正确。

输出 `slide-audit.json`；来源或目标小节无法完整对齐时单列为未验证，不混入通过项。缺失仍可能来自规则覆盖不足，不能一律解释为新的记谱类型。

波音/回音另用类型审计，同时核对音符归属与具体类型：

```powershell
node experiments/pdf-tab-prototype/audit-ornaments.cjs output/pdf-tab-prototype/benchmark-20261013-tie-padding experiments/pdf-tab-prototype/validation-summary-20261014-tie-padding.json
```

后续应继续处理跨行/跨页延音、演奏技巧、速度变化及多声部；保持独立实验，不能把核心谱面验证等同于全部演奏信息正确。

重复拨弦另按节拍、斜杠数量及演奏类型审计，仅在核心完全对齐的小节计入已验证：

```powershell
node experiments/pdf-tab-prototype/audit-tremolos.cjs output/pdf-tab-prototype/benchmark-20261014-tremolo experiments/pdf-tab-prototype/validation-summary-20261015-tremolo.json
```

此审计只处理可评估候选；多分谱、参考文件读取失败等候选中的预测另列在验证摘要的 `unverified_tremolos_outside_evaluated_cases`，不能计入正确数。
