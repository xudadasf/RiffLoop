# 图片时值与默认占位 GP（2026-10-27）

用户明确要求：识别不出的部分可以使用默认值占位，之后人工核对修改。本轮将数字 OCR、简单横梁时值识别和带标记的 GP 草稿真正接入桌面工作器。先前仅完成独立探针和报告、没有输出 GP 的状态不再作为完成标准。

## 当前流程

1. OCR 读取数字，像素字形间距区分单/双位品位，弦线与小节线定位弦号和小节。
2. `raster_beam_rhythm.py` 从裁剪图检测粗横梁，并要求数字附近存在连接符干；一至三条横梁分别提出八分、十六分、三十二分时值。保留横梁位置、方向、符干位置及覆盖率。无证据不会因音符数量合适就声称时值已识别。
3. 未知时值默认四分音符；剩余小节空间不足时，统一缩短为能容纳的普通时值。余下时长以休止占位补齐。已识别时值若与人工拍号冲突，整小节改为明确标注的默认节奏。可能同时起音的多弦音符暂按顺序保留并提示人工分组。
4. GP 内占位只标 `?`；逐小节位置、占位原因、低 OCR 分数音符写入 `.review.json` / `.review.md` 和 HTML 对照，避免长文字覆盖谱面。
5. 导出前验证每小节时值正好符合人工拍号，导出后重新读取 GP，验证音符、时值、拍号、BPM 和标记未改变。默认值仍为 100 BPM、4/4，可在窗口修改。

不使用原 GP 或人工抄谱作为识别输入；人工序列只用于输出后的独立核对。未知品位不编造为 0 品；漏识别导致的剩余时间是明确休止占位，并不证明原谱这里确实有休止。

## 复杂整页与限制

既有整页图输出到 `D:\RiffLoop-model-tests\pdf-tab-desktop\整页截图-tj5bec8p`。该图仍只有 103 个音符提案、60 条未解决 OCR 行，不能报告为准确转谱。本轮发现 Windows 下 `cv2.imread` 不能可靠读取中文目录，导致所有时值误走默认路径；已改为 pathlib 读字节再 `imdecode`，并增加中文目录回归测试。
