# 截图、照片与扫描 PDF 识谱试用

已将本地图片识谱接入桌面批量窗口。用户手动关闭旧窗口后，重新打开桌面“RiffLoop PDF 六线谱试用”快捷方式即可；新窗口标题包含“PDF / 图片”。本轮按用户要求未进行电脑界面自动操作。

## 处理路径

PNG、JPEG、WebP、BMP、TIFF 直接进入像素识别。PDF 中检测到含图片且没有六线矢量谱的页面时，整份 PDF 渲染为图片处理；含封面或文字页时，未定位到谱行会作为失败保留。原电子 PDF 规则与严格出口保持不变。独立图片文件分别处理，不自动合并成一曲。

`raster_tab.py` 进行 EXIF 方向归一、透明背景合成、灰度和暗色截图归一、基于长线的轻微倾斜校正、六条等距谱线定位与谱行裁剪。逐行保留输入图片、校正图、裁剪图与小节线估计。小节线会排除向下延伸的符干和中心不直的琶音线，双小节线合并为一个边界。检测到并排谱区时要求人工分列裁剪，避免错误拼接顺序。

调用已有 `local_model_probe.py` 与 Guitar Tab OMR 固定权重，以 CPU、4 线程、结构约束解码运行；每次加载验证既有源码/权重 SHA-256，安全加载权重，不另行下载或上传。输入清单只有图片路径和 ID，运行识别不接收 GP 参考。权重仍在 D 盘，不提交或重新分发。本轮没有改动模型权重。

模型输出必须正常结束、结构有效、小节数量与图像小节线估计一致，音符弦号/品位必须有效。遇到失败则保留谱区、原始预测、日志及问题，不将成功片段伪装成完整导出。失败谱行占用自己的小节编号范围，后续提案不重新填补这些编号。

## 草稿含义

- 保留模型提出的音符、弦号、品位、X 闷音和同时音符分组，全部要求人工核对。没有为单个音符编造置信度。
- 丢弃模型预测节奏，所有拍与休止的时值都明确标为未知，由草稿出口使用四分音符占位。不能据此判定时长或作为准确伴奏。
- BPM、拍号、定弦由窗口人工指定，默认 100、4/4、标准六弦定弦；GP 说明和 JSON/中文清单明确标注其来源。仅图片路径使用这些设置，电子 PDF 规则不受影响。
- 不导出延音、反复、变速和演奏技巧；小节编号是本次定位顺序号，不保证等同原谱印刷编号。
- HTML 结果页显示校正页、谱行裁剪、音符分组提案和每小节问题，用户可打开 GP 在支持的软件中修改。
- GP 写出前继续使用已有读回校验，检查序列化是否改变数据。这个检查不证明识别准确。

## 仍需改进

真实拍摄照片尚未独立验证。明显透视变形、书页弯曲、严重阴影、模糊、手写谱、多列和多声部不保证处理。请优先使用清晰截图或正对拍摄并裁出单列六线谱。六线谱检测也可能漏行，导出成功后仍必须对照完整原图检查范围与顺序；模型和几何检查不能证明无遗漏。

若只需试用，先加入一张清晰截图，查看 HTML 中是否正确裁出各谱行，再检查音符分组。后续优化应使用用户实际失败图片分别定位裁剪与音符识别问题，不能通过凑齐拍号或修改参考答案掩盖错误。
