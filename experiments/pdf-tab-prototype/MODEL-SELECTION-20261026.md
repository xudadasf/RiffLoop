- 先保存原始预测及哈希，再读取已有参考结果。轨道沿用旧基线的选择，不按模型输出重新挑选轨道。
- 评测主声部的拍时值、附点、连音比例、休止、装饰音和延音目标数量；整小节休止按拍号恢复时长。模型侧只使用 PDF 的拍号上下文，参考侧使用 GP 的拍号。
- 小节数量错误时整段判失败；不跨小节重新对齐，不按拍号补音，不丢弃失败样本。JSON 格式错误、不确定输出和截断也保留为失败。

## 本机配置与候选范围

本机约 31.7 GiB RAM，RTX 4070 Laptop GPU，8188 MiB 显存。原 Python 的 PyTorch 为 CPU 版；专用模型在独立环境运行，视觉模型通过 CUDA 12.4 的 llama.cpp b11889 运行。

- **Guitar Tab OMR**：194,331,017 字节权重，ConvNeXt tiny + transformer，输入 1200×224。适合已裁出的单行数字六线谱，公开词表没有 GRACE、掌根闷音和顿音等专用 token，不能假定覆盖现有全部播放语义。源代码和权重固定版本、逐文件 SHA-256 校验；使用 `weights_only=True`，关闭编码器另行下载。
- **Qwen3.5-4B Q8_0**：语言权重约 4.48 GB，视觉权重约 0.67 GB。已实测 GPU 运行，生成速度约 45 token/s；运行时显卡总占用约 7 GB，包含其他程序，不能当成模型独占用量。
- **Qwen3.5-9B Q4_K_M**：语言权重约 5.68 GB，视觉权重约 0.92 GB。全部放入显卡时余量较小，采用运行库自动分配并保留余量；首次服务预检为 26/33 层在 GPU。独立命令行的实际分配记录在每段日志中，不能假定始终一样。
- **Qwen3.8-27B**：虽更新，但仅 4-bit 参数的理论体积也约 13.5 GB，尚未做这台电脑的 CPU/GPU 混合实测，不能宣布它效果差或不可运行。
- **WeVisOne-VL-4B**：官方定位包含定位、检测、OCR 等视觉感知能力，可作为教材谱区定位候选；本轮未验证六线谱节奏，不将一般 OCR 成绩当作识谱成绩。

这里没有“所有本地模型中最好”的证据。当前结论只针对实际测试的模型、量化、提示词、输入裁剪及运行库组合。运行日志中的 M-RoPE 位置警告在上游也有报告，但尚无证据证明它就是本轮识别错误的原因，不能把全部失败归咎于它，也不能据此宣称模型原始权重同样差。
