## 结论

后续决定：用户已批准按计划修复，但明确保留 PDF 底栏原有透明效果；下方“不透明底栏”建议不实施。修改与验证进度见 [0.25.56](releases/0.25.56.md)。

整体已经有清晰的练习工具结构：深色框架、首页继续练习、三种模式入口、底部播放控制和右侧设置。首页和 GP 谱面的完成度较好；PDF 和视频的设置仍显零散，说明文字及次要信息的可读性不足。建议保留当前结构与配色，先修可读性和操作保护，再统一控件样式，最后压缩首页重复内容。

## 优先修改项与验收方法

### P1：PDF 底栏在白谱纸上辨识度不足

证据：run2 `01-pdf-main.png`、`11-pdf-follow-empty.png`、`13-pdf-follow-recorded.png`。半透明材质透出白色纸张，中间页码、缩放、进度及卡片说明变成浅灰叠浅灰。对低视力用户、远距离练琴尤为不利。

原因依据：`RiffLoop/PDF/PdfPracticeView.swift:174` 使用 `.ultraThinMaterial`。建议给底栏稳定的深色底色，保留轻微材质效果；分清可用、禁用、选中状态，不依赖背景图来形成对比。

验收：同尺寸白谱、灰扫描谱、深色页面及滚动位置分别截图；页码/BPM/音量/跟谱状态清楚可辨。按实际字号测量对比度，并实机确认，不凭截图宣称无障碍合规。

### P1：续签说明显示不完整

证据：实机 `04-signing-help.png`，第 1～5 条等长句末尾变成省略号。

原因依据：`RiffLoop/UI/HomeView.swift:476` 起将所有长文放入固定空间的 VStack，没有 ScrollView。建议正文可滚动、段落完整换行，按钮固定在底部；步骤标题简短，解释跟在下面。

验收：横屏及竖屏、默认及较大字号，7 步全文均可读到，关闭和重新检测可达。只改呈现方式，不改签名流程。

### P1：PDF 删除/重新记录需要保留原轨迹的退出路径

证据：run2 `13-pdf-follow-recorded.png` 显示直接的“重新记录”“删除轨迹”。只读代码核对：`PdfPracticeView.swift:516` 直接调用动作；`PdfPracticeViewModel.swift:639` 删除后立即保存；`:579` 重新记录直接清空当前点集。没有在真实 iPad 或模拟器执行删除。

建议：删除前明确确认；重新记录先创建草稿，保存时替换，取消时保留旧记录。该项涉及数据行为，应单独最小修复，不混入纯视觉整理。

验收：取消删除、取消重录、退出页面、重新打开原 PDF 后旧轨迹均保留；明确保存新轨迹后才替换。使用临时测试 PDF 验证。

### P2：统一三种模式设置的分组与标签

证据：GP 分组表单与视频/PDF 的散列控件明显不同；run2 `05-video-metronome-on-top.png`、`02-pdf-metronome-top.png`、`08-pdf-accompaniment-selected.png`。

建议：保留右侧面板，统一为“播放/速度、节拍设置、音量、高级同步”几组；选择项常驻显示名称，拍子分组输入标题不依赖 placeholder；每个音量显示百分比及 100% 基准。PDF 保留独立节拍器和跟谱，不为了外观重新绑定。高级毫秒对齐默认折叠。

验收：三种模式相同概念同名、同单位，常用设置不必滚到面板底部；不同拍号和大字号下不挤压。

### P2：GP 声音页将诊断收起

证据：run2 `09-gp-sound-top.png`、`10-gp-sound-bottom.png`。普通练习设置中出现成段技术日志，占据大部分面板。

代码核对：`GpPracticeView.swift:565` 仅判断日志非空，没有 DEBUG 限制；`GpWebViewModel.swift:503` 接收诊断后填充。不是仅凭模拟器 Debug 外观猜测。

建议：放入默认折叠的“故障诊断”，只在错误时给一句可执行提示；保留复制诊断能力以便排错。内嵌伴奏的技术实现说明也改成用户需要的功能说明。

### P2：底部摘要精简、常用信息放大

证据：实机 `05-gp-main.png` 的节拍器、声音、轨道摘要多处截断。建议按钮仅保留名称和一项关键状态（例如“循环关闭”“63 BPM”“音量 75%”“轨道 1”），详细信息留给面板。谱面视图和现有缩放范围保留。

验收：长轨道名、长文件名、低速/多拍号、120% 与 150% 谱面下检查，不以缩小文字解决拥挤；演奏距离下能辨认主要按钮。

### P3：首页、文件库和文字细节

- 首页：保留继续练习及预览；签名正常时缩为一行，到期临近再突出。最近项目首页显示少量，完整列表承接查找；热力图补日期与练习量提示。
- 最近项目：增加类型筛选/搜索前先核对真实文件量，统一日期本地化及返回文字。
- 文件库：顶部用“导入文件”文字加图标；常用打开优先，改名/删除放“更多”或编辑态；改名用明确“保存”代替仅勾号，面板高度按内容调整。
- BPM：保留已通过的数字面板，301 时显示“请输入 30–300”，而不只是禁用应用。

以上是产品设计建议，不能把审美判断记为功能故障。

## 建议实施顺序

1. 续签说明换行/滚动、PDF 底栏对比度，各自单独最小改动并同屏对比。
2. PDF 轨迹删除/重录保护，专门验证取消/退出/重开和保存行为。
3. 统一面板标签、音量值、底部摘要、折叠诊断。
4. 最后再调整首页签名卡、最近列表与文件库操作，不更换整个视觉风格。

## 未覆盖的状态与边界

本轮覆盖清单中的主要页面和面板，不等于每个状态组合：未补拍多轨 GP/内嵌伴奏、有 A/B 后的全部阶梯状态、所有拍号菜单、PDF 实际滚动复现与中断恢复。模拟器 PDF 两个记录点来自测试时钟，不代表实机翻谱准确。未做竖屏、分屏、浅色、Dynamic Type、VoiceOver、触控目标尺寸及长时音频同步验收。系统文件选择器的出现不代表微信外部打开已验收。

后续修复必须用对应状态截图和有针对性的行为验证复核；保留原 Apple 账号与 Bundle ID，覆盖安装、不卸载。此次没有通过截图宣称应用无 bug。
