# 0.25.60 (104) — GP 音频与异常记录

跟踪：GitHub Issue #7。原始设备材料保存在本地 `output/diagnostics-20260909`，未上传用户谱面或原始诊断包。

## 证据与修改

- 0.25.59 MetricKit 报告确认一次 scene-update watchdog 终止，限时 10 秒。安装 IPA 的 Mach-O UUID 与报告一致（A5C79A0B-B33C-300D-87CC-446272FDC4E6）；主线程 RiffLoop 返回地址偏移 343392 的前一条指令调用 Foundation.NSLog。删除该同步调试输出及独立日志写入，保留后台异常记录。
- MetricKit 同时报告 1158 MB 累计写入，主要栈位于 ReproductionStore.writeEvent。检查点改为追加新增事件和三段轮换，去除每个归档事件重复写 manifest、普通事件逐条 fsync；新增有上限的异常索引。
- 9 月 8 日 22:04 循环预备拍期间，Spark MINI USB 先断开后重连，AudioContext 从 running 进入 suspended。设备断开/会话中断时取消预备拍和播放意图；下次播放重新激活音频会话。WebContent 终止后重载原文件并保持暂停，重复失败停止自动恢复。
- 修补随包 alphaTab AudioWorklet 异步初始化与 pause 的竞争：已取消的 source 不得被晚到的初始化结果重新连接；未启动 source 的 stop 不抛 InvalidStateError。用真实导出类及受控异步初始化回归该路径。
- iPad 使用原生伴奏时不再将整份 GP 另传隐藏播放器，减少重复解析与内存占用。
- 合成总音量上限 400% → 1600%；节拍器和预备拍共用上限 300% → 600%。保留 GP 轨道混音和演奏强弱。对合成器/节拍器/预备拍共用音频输出加软峰值保护；低于 0.75 的样本保持线性。
- 左手机能原文件的 432 个音符，MIDI 音高和起始 tick 与谱面一致。加入音频设备输出延迟补偿：优先浏览器 outputLatency + baseLatency，缺失时采用原生输出延迟（已含 IO buffer）；暂停/跳转清除旧位置回执。依据 [Web Audio 规范](https://www.w3.org/TR/webaudio/#dom-audiocontext-getoutputtimestamp)，不使用 currentTime 与输出时间戳的差值推算延迟。外接 Spark 的最终听感同步仍需实机验证，不能由 MIDI 对照测试代替。
- 播放位置长期无进展时保留异常现场并退出卡住的播放意图，使下一次播放可重试；捕获渲染回调的堆栈，补足 file URL 下原有 Script error 无细节的问题。
