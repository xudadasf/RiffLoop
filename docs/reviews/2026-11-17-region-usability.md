# 识别设置与四角调整：2026-11-17

## 根因与行为

旧设置模型要求先分别应用输入，而保存入口又被未应用状态拦截。真实模型回归在提交 `efa0f0525eaea6ccad2d2940b39246e9e08689a5` 的 [CI 44028906028](https://github.com/xudadasf/RiffLoop/actions/runs/44028906028) 失败：填写合法 BPM/拍号后保存，保存闭包未收到计划。新模型一次校验并保存全部字段；识别前调用同一保存路径；排序、选择和追加区域保留正在填写的值。无效输入精确指出字段，写入失败保留输入供重试。

框选页沿用立即单击选中和单一删除按钮。双击或「调整区域」显示四个 44 点触控目标；拖动预览、松手保存，保持框的 UUID、编号与顺序。坐标按缩放后的页面尺寸归一化，限制在页面内、不能翻转。并发修改同一框时提示冲突，重试不得覆盖外部几何修改；其他新增框继续保留。有效编号在选框、翻页和下一步前自动提交。

新计划使用统一间隔，默认 1、范围 0–99，末尾不追加，不从旧逐框间隔复制到新计划。旧计划的混合间隔在用户主动填入统一数值前保留；原框几何、编号及旧计划不会被读取动作迁移改写。核对页「小节 / 复制」可在当前小节前后插入 1–99 个空白小节，沿用当前局部拍号/明确设置的速度，保留已有音符，并可撤销、重做。

测试期间还处理了两个首次操作问题：独占的单/双击手势会延迟选择，打断紧接着点击编号输入框的焦点；改为立即响应的 Button 配合同时识别双击，原快速输入测试未加延时。核对页的静态按钮可能早于原生草稿注入而出现；浏览器延迟注入测试复现旧按钮提前可操作，新版在草稿渲染后显示编辑控件，加载期间保留返回入口。原生完整流程测试继续使用真实识别和草稿存储，未以假编辑页面代替。
