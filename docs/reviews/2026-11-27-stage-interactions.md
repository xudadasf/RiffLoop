# GP 阶梯交互核查 — 2026-11-27

## 现场证据与可重复问题

用户确认发生在 GP 点谱、调整区间或打开设置附近。USB 读取的已安装版本为 0.25.89（133）。昨晚会话只保留 23:39:26–23:40:33 的末尾事件，没有覆盖退出瞬间，不能用这段记录认定唯一触发操作，也不能把音频路由事件认定为原因。

在未修改生产代码的 e10004c 上，[原生基线测试](https://github.com/xudadasf/RiffLoop/actions/runs/45927348288) 跑完 9 项：区间外点按、取消重选、确认重选三项失败，共 40 条失败断言；区间内点按、暂停继续/停止、音量/缩放/轨道以及明确关闭操作通过。

根因有两条：普通定位复用了关闭 A/B 的路径，顺带关闭阶梯；开始拖选就提前销毁 native 已确认范围及阶段，而 WebKit 仍保留已确认范围，取消无法回滚。修复让预览不破坏已确认状态，只有提交时才替换范围。

扩展核查另发现旧长按计时器在清除范围后仍可提交、自动恢复共用普通打开曲谱流程丢失临时练习状态，以及预备拍过渡取消的状态同步缺口。它们是独立的代码路径问题，未声称都对应昨晚现场。

## 行为边界

| 操作 | 约定 |
| --- | --- |
| 阶梯中点到 A/B 外 | 保留范围、阶段、速度与进度；不跳出区间。普通 A/B 仍沿用原来的区间外定位规则。 |
| 区间内轻点 | 正常定位，保留阶梯。 |
| 长按预览后取消 | 保留原区间与阶段进度，保持暂停，手动继续。 |
| 确认新的 A/B | 自定义阶梯保留当前阶段和往返方向，当前阶段重新计轮/计时；旧固定步长阶梯沿用提交新区间后恢复手动速度的规则。 |
| 预览期间播放或选阶段 | 暂不可用；迟到播放/完成消息不启动计时或多记轮数。停止仍可用。 |
| 清除区间、关闭 A/B、切换整曲 | 明确退出；废弃旧手势，迟到松手不能反转选择。 |
| 暂停与继续 | 保留当前阶段进度。 |
| 停止 | 自定义阶梯回到第一阶段，计划仍启用；保留既有固定步长规则。 |
| 选择起始阶段、修改计划 | 保留已有明确准备/重启语义，不把普通暂停改成重置。 |
| 音量、显示轨道、缩放、预备拍设置 | 不关闭阶梯；预备拍过渡被取消时明确暂停，不自动续播。 |
| 音频断开、进后台 | 暂停并冻结进度，重新连接或回前台不自动播放。 |
| GP 谱面自动恢复 | 仅相同文件内容与本次加载事务可恢复区间、阶段及冻结进度，不自动播放；恢复期间暂禁用循环参数编辑，避免旧状态覆盖新选择。 |
| 普通换文件、离开 GP | 沿用原来的临时练习状态清理规则。 |

## 验证范围

- `GpStageInteractionTests` 通过实际模型公开入口覆盖播放/暂停两种状态、bounce 回程、时钟冻结、旧阶梯、整曲、明确退出、迟到事件、音频路由及独立节拍器配置隔离。
- `GpWebPlaybackIntegrationTests` 使用真实 WKWebView、alphaTab 和 GP fixture，检查取消/提交后的 JS 已确认范围、实际回环与阶段 BPM；并验证自动恢复隔离。
- JS 手势回归从实际生产 factory 与公开命令构造，验证待触发/已开始拖选、取消及迟到事件。修改前失败，修改后通过。
- 完整 iOS CI 覆盖 iPad mini 界面、原生播放/识别编辑回归及日志写入预算；结果以 GitHub 同一提交的检查记录为准。专项流程不替代正式 `ios-ci.yml` 发布门槛。

以上不等于真实 iPad 的每种手指触控或扬声器听感都完成长期验证。本轮未安装更新，未修改设备资料、续签缓存、Android 或练习设置文件格式。
